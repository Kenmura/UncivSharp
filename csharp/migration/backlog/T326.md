  - Reset (stale claim (3 days); reset for a fresh implementer); was 'In-Progress [Claude]'.
  -   - Implemented. Deliverable is the layout-matrix resize-phase assertion, which found and now covers a real bug: `UiTheme.Fit`'s LayoutChanged callback re-measures a visible tip synchronously, but `RichTextLabel.GetThemeFontSize` still resolved against the control's PRE-resize theme cache (Godot refreshes control theme items in a later frame). A tip shown across a live resize was therefore measured at the old font size: at scale 2.5 the width collapsed to the minimum (300 instead of ~491) and at scale 1.5 it stayed 196.4 instead of ~294.6. Fix: `TooltipHost.TextWidth` reads `normal_font`/`normal_font_size` from `theme.Theme` (the `UiTheme` resource that Rebuild mutates synchronously) instead of through the control. No new public API; the hidden path still resets the width to `theme.Px(MinTextWidth)`.
      - Scenario: WidgetGallery.TipText ("Cities need food to grow.") is wide enough to be measured and stays between the min/max clamps at every scale of the cycle. ShowTip uses the real `Point` + `Advance` hover path once, in the first resize phase, and the tip stays VISIBLE across 1366x768 -> 3840x2160 -> 1366x768 -> scale 1.5 -> scale 1; each phase asserts the shown text width is within 5% of width-at-scale-1 * live scale (the font rounds its size to whole pixels, so it is only proportional). Showing it again per phase would re-measure it and hide the bug, so the show step runs only in the first phase. The existing hidden-width `Wrong` check is kept and `Wrong` skips the tooltip entry only while the tip is showing (it would legitimately not be the minimum then); it still runs at all six matrix sizes and in the first resize phase.
      - Mutation check: with the Fit callback reverted to only reset the width while hidden, the reduced layout-matrix run FAILS at resize-3840x2160 ("the visible tooltip text is 196.40001 wide, the live scale 2.5 gives 491.00003") and resize-scale-1.5 ("196.40001 ... gives 294.6"); passes at the scale-1 phases. With the fix the full layout-matrix passes with 0 problems.
      - Also ran the `tooltips` scenario (goldens of real tooltips): PASS, all 7 captures match, so the corrected measurement does not change the rendered tips at a steady scale.
