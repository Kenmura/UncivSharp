### T405 In-game saves dialog uses the unbound user scale for its breakpoint (differs from the game UI at user scale > 1)
- State: Done
- Depends: T321
- Source: T321 review: App.ShowGame builds the in-game SaveController with its own UiTheme that no ScreenManager binds. IsCompact now derives the breakpoint from Size.X / theme.Scale, but an unbound theme has no auto-scale, so at 1600x900 with user scale 1.5 the bound game UI is Compact (1600/(1.5*1.25)=853) while the saves dialog is Regular (1600/1.5=1066).
- Fixtures: none
- Deliverables: Bind the in-game SaveController to the game theme (or pass the effective auto-scale/logical width), so its breakpoint and pixel sizes match the UI it floats over; layout-matrix assertion at a large window with user scale != 1; no change to the menu controller.
- Gate: dotnet build -warnaserror && dotnet format --verify-no-changes && dotnet test; from csharp/: Unciv.Godot.Harness/tools/run-scenario.sh layout-matrix
- Claimed: 2026-11-05T07:00Z
- Notes:
  - Root cause: App.ShowGame built the in-game SaveController with its own `new UiTheme(registry)` that nothing binds, so its auto scale stayed 1 and the breakpoint came from `width / 1` instead of the game screen's bound `width / (user scale * auto scale)`.
    
    Fix:
    - GameScreen raises `SharedThemeChanged` with the freshly built, bound theme at every Start (new game, load, hotseat hand-over).
    - App.ShowGame subscribes `saves.UseTheme` to it (the main-menu controller is untouched; its theme is bound by ScreenManager).
    - SaveController.UseTheme swaps the theme, re-registers the LayoutChanged handler, re-themes an open dialog and re-applies Layout; the existing width/scale breakpoint rule then matches the game UI exactly.
    - MenuScenario and SaveLoadScenario, which emulate App.ShowGame, now share the game theme too, so the in-game load path (a new theme from `screen.Start`) is exercised.
    
    Test: new layout-matrix InGameSaveSteps builds a real GameScreen at 1600x900, sets the user scale to 1.5 and refits (SetScale alone leaves UiTheme.Breakpoint stale; a real user-scale change refits through the viewport resize). It asserts the game UI is Compact at scale 1.875 (1600/(1.5*1.25)=853) and the sharing dialog has 3 columns and the 0.94 Compact panel share. Mutation check: making SaveController.UseTheme a no-op made both the 3-column and the panel-share assertions fail (and the matrix's problem list non-empty); restored afterwards. The unbound width fallback from T321 is kept as a defensive case (now named saves-unbound).
