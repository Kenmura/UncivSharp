- Notes:
  - Implemented `bench --repeat N` (1-20, default 1) for every scenario. Each run is a full fixed-seed game; the report detail comes from the median run (the run whose late median is the median, lower middle for an even count) and the scenario-level `lateMedianWallMs` / `totalSeconds` are the medians across all runs, with `...Min`, `...Max` and `...SpreadPercent` ((max-min)/median*100). The JSON gains `repeat`, those spread fields, and a `runs` array (per run: turns played, late median, total seconds); the text summary prints each run and the across-runs median/spread. Repeat 1 keeps the old detail and adds only the new fields.
    `--golden` now compares the median run and additionally requires every repeat to carry the same per-turn state hashes: a run that differs is reported as nondeterminism (run/turn) and exits 1, never averaged away. Usage/help and migration/design/PERFORMANCE.md document the option; the old follow-up bullet is removed.
    Tests (BenchTests): pure median/spread cases (odd, even, empty, zero spread), the repeat JSON/text report, the repeated golden path ("median of 2 runs"), hash disagreement (value and length) through the public ScenarioRuns seam, the medium scenario path, and `--repeat` validation (0, 21, non-integer, missing value all exit 2). Demo: small 5 turns `--repeat 3` printed run late medians 36.8/64.2/60.2 ms, across-runs late median 60.2 ms (min 36.8, max 64.2, spread 45.5%), total 0.5 s (0.4-0.8, spread 74.6%) - the spread is the machine noise this option exposes.
