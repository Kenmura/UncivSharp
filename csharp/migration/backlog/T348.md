- Notes:
  - Chat: LobbyHost now enforces the same bounds as in-game chat (new LobbyLimits, injectable for tests: 500 chars, 5 lines/10 s). Blank lines are dropped, long lines cut, the excess dropped silently (never queued); the sender name is the bound seat's, never the frame's.
    Kick/ban reason: JoinRefused gained an optional `reason` (additive, no protocol bump, golden in NetProtocolTests). Kick sends `kicked`, Ban sends `banned` and records the key in an in-memory ban list (lives only as long as the lobby, like the password; Unban removes it). The ban check runs after admission, so a probe without the password learns nothing (test Ban_DoesNotLeakThroughABadPassword). Reason is control-stripped and cut to 200 chars host-side.
    Rejoin by name: a dropped human seat keeps its display name; a new key that authenticates with the same name reclaims it (nation/colour kept, the absent key's binding dropped). Only disconnected seats are reclaimable, so a connected player is never displaced (a deliberate trust decision for friends lobbies, documented in SERVER.md 6.5).
    UI: a Ban button sits beside Kick; a reason popup (KickBanView, a Modal) collects the optional reason. The removed player sees the exact reason (JoinRefusedEvent.Reason -> LobbyModel.RefusalText). Chat input capped at 500 (SocialModel.MaxChatChars).
    UI at all sizes: LayoutMatrixScenario now seats a second player so the Kick/Ban buttons and the reason popup are checked at every size; layout-matrix passes with 0 problems.
    Scenario: new `lobby-admin` (chat relay, kick-with-reason, ban-with-reason and rejoin refusal, rejoin-by-name) with goldens; the existing `lobby` scenario was extended for the reason popup and its goldens re-recorded.
