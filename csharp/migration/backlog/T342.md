- Notes:
  - - Implemented `IncrementalViewBuilder` (Unciv.Core/Net/Visibility): per-recipient state = last snapshot + canonical JSON element of every tile + map index + map-content/reveal revisions. A command rebuilds only currently visible tiles, visibility flips, newly explored tiles (including a tile a unit explored and left in the same command), event positions and units; an unchanged `TileDto`/`UnitDto` is reused by reference. The rest of the snapshot (cities/civs/diplomacy/notifications) is built as before, but the view hash is computed from cached per-tile canonical JSON and the diff is built from the rebuilt keys (`SnapshotDiff.ComputeIncremental`; unit order is derived exactly like the full diff).
    - Fog semantics: a human viewer's explored-fogged `TileDto` carries only remembered improvement/owner and static terrain/resource. Terrain/resource/site changes are signalled by a new transient `TileMap.MapContentRevision` (bumped in `Tile.SetTerrainFeatures`, `TileResource` and `SetTileResource`), and resource reveal by the viewer's tech/policy counts (`ViewDeltaBuilder.RevealRevision`). Either changing, a non-human/spectator viewer, a stale/foreign previous snapshot, or a missing mark falls back to the full build and reseeds. The revision is `[JsonIgnore]`/transient, so saves and state hashes are untouched (`bench --golden` small 50 and medium 200: identical).
    - Equivalence: `IncrementalViewBuilderTests.ScriptedLateGameCommands_ProduceByteIdenticalSnapshotsAndDiffs` drives a scripted two-human game and compares every command's full/incremental snapshot canonical JSON, diff, events and view hash, applying the diff to a mirror; `GameHostParallelViewTests` compares every encoded host frame (2/4 recipients, 3/6 rounds), with and without parallel views, and after dropping the builder state between commands. Fallback cases have their own tests (AI viewer, stale state, map-content change, tech/policy change, missing visible set). Existing `SnapshotDiffTests` covers a diff applied to the wrong base (client resync).
    - Measured on the new `bench --scenario six` (6 majors, 3 human seats, 6 city states, Medium, 200 turns, 22 cities/~195 units; 3 recipients, last 5 turns, 90 commands): interleaved full/incremental runs, Release, shared machine. Host cost per turn (capture+build+encode): full 63.6 / 64.4 ms -> incremental 49.1 / 46.8 ms (median 64.0 -> 48.0, -25%). `Host.BuildDelta` per recipient-command 1.037 / 1.065 -> 0.803 / 0.757 (median 1.051 -> 0.780, -26%). 267/270 builds incremental; 3 full builds are the reveal fallback. Engine late median was unchanged within noise as expected; adding host cost back gives ~228 -> ~213 ms/turn (-7%) for 3 players. Numbers and method in `migration/design/PERFORMANCE.md` ("Result of T342").
    - Default: incremental ON (`HostLimits.IncrementalViewBuilding = true`, `ServerOptions` default; `--no-incremental-views` opt-out). It composes with `--parallel-views` and helps one player too. Deliberate deviation none in engine logic (only a transient revision); no engine state or hash change.

  - - Review notes (DeepSeek-Review, 2026-11-10): changes requested. **Blocking (determinism/parity):** `IncrementalViewBuilder.Key` (both overloads, `IncrementalViewBuilder.cs:251-253`) formats the tile key with the current culture (`$"{x},{y}"`), while `SnapshotDiff.TileKey` and the `rebuiltTileKeys` set it is matched against use `CultureInfo.InvariantCulture` (`SnapshotDiff.cs:46`). Under a non-invariant ambient culture (the repo's own `OddCulture` pattern; real `sv-SE` uses U+2212, `ar-SA`/`fa-IR` also differ) a changed visible tile at a negative coordinate — normal on every rectangular/hex map — is not found in `rebuilt`, so `SnapshotDiff.ComputeIncremental` silently drops it from `Changed`. The incremental snapshot/hash are right but the diff is not: a client applying it gets a hash mismatch and resyncs, and the frames are not byte-identical to the full build. Reproduced with a scratch test: set `CultureInfo.CurrentCulture = OddCulture()` (negative sign `~`), change one visible tile's shown improvement at `x<0`, then `fullDelta.Diff != built.Delta.Diff` while both after snapshots are identical; `Apply(before).ViewHash != built.Delta.ViewHash`. Fix: use `CultureInfo.InvariantCulture` in `Key` (or a `(int,int)`/`HexCoord` key shared with `SnapshotDiff.TileKey`) and add a culture-independent test. This is the same bug class the repo already pins in `EndToEndDeterminismTests.HexCoordTextIsCultureIndependent`.
      - Non-blocking (residual fog-reuse gap, mutation-probed): a change to a human viewer's remembered fogged-tile state (`SetLastSeenOwner`/`SetLastSeenImprovement`) that does not bump `MapContentRevision`/`RevealRevision` is reused stale. Base-game callers are covered (visible tiles are rebuilt; the only whole-map reveal is a tech, and its tech count changes `RevealRevision`), but a mod/future unique on a building/unit would diverge. Consider bumping a viewer-memory revision only when the remembered value actually changes, or pin the invariant in the class docs.
      - Non-blocking (test strength): `IncrementalViewBuilderTests.ScriptedLateGameCommands_...` counts `fallbacks` but never asserts that a meaningful number of builds were incremental; the host/bench tests do. Add `Assert.True(incremental > 0)`/`fallbacks < accepted` there so a regression that always falls back fails the equivalence test itself.
