  - Implemented (Claude, resumed after a dead agent). ROOT CAUSE (reproduced on the real display, DISPLAY=:0 KDE, RTX 5060 Ti + Intel Arc iGPU): App.cs re-ran ClientSettingsApplier.Apply on EVERY ClientSettingsService.Changed, and Apply forced window.Mode from the stored WindowMode ("Windowed" by default), MinSize and ContentScale. Any unrelated settings write (a tutorial marked seen, toggling resources/yields, console history, build templates) therefore un-maximized/un-fullscreened a window the player had just changed by hand, firing a second resize: the "freak out". Fix: OptionsModel.WindowNeedsApplying(previous, now) (tested); Apply takes the previous settings and touches the window only at start or when WindowMode/UiScale changed; App.cs tracks the last applied settings. Harness scenario window-resize (WindowResizeScenario): maximize/restore/fullscreen/exclusive fullscreen, an unrelated settings change while maximized (FAILS without the fix: verified by passing null as previous, "an unrelated settings change leaves the window mode alone"), a 4-size burst with no frame between, and 640x480, 3840x2160, 3840x400, 400x3000, 1x1, 8x8, 100x60 sizes; asserts viewport==window, camera finite, frames advancing, LayoutChecks.Problems empty at normal sizes. Env: UNCIV_RESIZE_REAL=1 logs each size; UNCIV_RESIZE_QUALITY=Low|High|Ultra applies that preset. run-scenario.sh timeout for it is 300 s (Xvfb takes seconds per size change).
    Platform results (all PASS, exit 0, no crash, no exception): Forward+/Vulkan on the RTX 5060 Ti at Low and Ultra; gl_compatibility/OpenGL (Mesa Intel iGPU) at Low and High; software Xvfb via run-scenario.sh. Window manager here maximizes to 2560x1368, fullscreen 2560x1440; sizes above the screen are clamped by the WM.
    COULD NOT REPRODUCE: a crash or exit-code failure at any size/mode/renderer/quality, NaN or divide-by-zero in MapCamera at 1x1 (the WM clamps to 64x64, MinSize is 640x480 only after Apply runs in App, not in the scenario), runaway layout rebuilds (Viewport.SizeChanged fires about 2x per resize, no per-frame churn), SSAO/SSR/MSAA target reallocation failures at Ultra. Not tested: Wayland-native (the session ran through XWayland on :0), Windows/macOS, Ultra on gl_compatibility (not offered by the graphics model). Seen but pre-existing and benign: Godot warning "Nodes with non-equal opposite anchors will have their size overridden after _ready()" from Modal.LayoutIn (Modal.cs:119) at GameScreen start. The scenario applies no stored settings, so in the real app (MinSize 640x480 set by Apply) a crash that depends on content scale (UiScale != 1) was not exercised.
